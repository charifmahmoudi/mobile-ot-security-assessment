# Validation plan when interviews are unavailable

## Principle

Absence of interviews does not authorize fabricated confidence. Replace opinions with progressively stronger behavioral evidence.

## Evidence ladder

| Strength | Method | What it proves | What it does not |
|---:|---|---|---|
| 1 | official market/operator research | sites and structural context exist | buying intent |
| 2 | job/tender/OEM signal analysis | technologies or needs appear in ecosystem | exact installed base |
| 3 | landing-page/checklist conversion | message attracts attention | willingness to pay |
| 4 | request for quotation or partner proposal | buyer will invest effort | purchase |
| 5 | signed pilot scope/LOI | organizational interest and authorization path | recurring value |
| 6 | paid readiness/baseline | willingness to pay for outcome | software retention |
| 7 | repeated paid use/license | product-market evidence | scalable unit economics |
| 8 | renewal and partner-sourced expansion | durable value | global transferability |

## Pre-prototype experiments

1. **Report-before-product:** create a realistic sample inventory/evidence report and quote the service.
2. **Concierge baseline:** use approved existing tools in a lab/authorized engagement while manually applying the proposed workflow.
3. **Hardware feasibility:** test phone/NIC/TAP combinations before app UI.
4. **Golden-packet corpus:** prove identity depth and safe behavior using emulators and owned devices.
5. **Connector spike:** import three representative inventory formats and export normalized assets.
6. **Procurement test:** submit a complete fixed-price offer through a partner.
7. **Channel test:** ask integrators to allocate delivery capacity or margin-bearing co-sell effort—not merely say they like the idea.
8. **Paid training:** sell an OT safe-discovery workshop as a precursor.

## Prototype scorecard

| Measure | Minimum decision threshold |
|---|---:|
| vendor/family identification in owned corpus | ≥90% where a specific identifier exists |
| false model-level identification | <1% |
| unintended state-changing packets | 0 |
| active query profile golden-packet match | 100% |
| operator cancellation | <1 second to stop new sends |
| 100-asset case on target phone | completes without OOM |
| evidence claim reproducibility | 100% sample |
| report reconciliation time reduction | ≥30% versus documented baseline workflow |
| paid pilot or equivalent binding commitment | 2 organizations |
| partner willing to deliver second assessment | 1 |

Thresholds are product decisions and may be revised with evidence.

## Negative tests

Stop or narrow the project if:

- mirrored capture needs hardware too expensive or fragile for target economics;
- identity accuracy is mostly port/OUI-level;
- customers require only continuous monitoring and reject field baselines;
- partner support cost consumes more than 25% of recurring revenue;
- active identity queries cannot be bounded safely;
- public/open data cannot legally support the planned knowledge catalog;
- Android OEM fragmentation forces an unmaintainable matrix.
